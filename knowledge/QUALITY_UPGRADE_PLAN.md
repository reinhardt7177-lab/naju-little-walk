# 나주 산책 퀄리티 업그레이드 실행 계획

작성: 2026-10-01. 선행 결과는 `tablet-ui-completion-2026-10-01.md`와 운영 버전 56이다. 이 문서는 후속 작업의 기준과 진행 상태를 관리한다.

## 목표와 원칙

실제 장소의 특징을 알아볼 수 있는 풍경과, 태블릿에서 이해하기 쉬운 산책 경험을 만든다. 디테일 개수보다 사진과의 일치, 눈높이에서의 규모감, 안정된 조작을 우선한다.

- 사용자 Blender 수정본은 덮어쓰지 않는다. 새 편집본과 변경 전 자산의 해시를 남긴다.
- 지형·건축·식재는 Blender에서 제작하고 GLB로 내보낸다. Three.js는 표시·조작·거리별 표시를 맡는다.
- 확인한 윤곽과 시설, 사진에서 추정한 치수와 수종, 연출용 재질을 구분한다.
- 계절·촬영일이 다른 사진을 하나의 현재 실측 장면이라고 주장하지 않는다.
- 실제 잔디 빈 공간과 통행 폭을 보존한다. 임의 건물·나무로 모든 공간을 채우지 않는다.

## 이번 제작 실행

빛가람 공원의 나무를 먼저 보강한다. 게시 중인 GLB를 현재 상태의 기준으로 삼아 새 Blender 파일을 만들고, 기존 줄기의 바닥 위치·높이·수관 폭을 측정한다. 같은 자리에 공유 수형을 배치하며 기존 지형과 시설은 보존한다. 가까운/먼 수형은 동일 변환을 사용하고, 새 바닥 장애물은 추가하지 않는다.

표시용 정리 작업은 작은 단위로 나누어 브라우저가 안내창·취소·다른 장소 선택을 처리할 기회를 준다. 동기 버전과 동일한 경계·재질·노드 속성을 유지하는지 비교한다.

## 검증 게이트

- 새 모델: 원본 스냅샷, 나무 배치 전후 좌표, 공유 원형 개수, 가까운/먼 쌍의 변환, GLB 내부 이미지와 형식, 압축 원본 일치.
- 형상·재질: 같은 카메라의 전후 Blender 렌더와 실제 웹 산책 화면. 검사 통과만으로 시각 완성을 주장하지 않는다.
- 보행 변경 시 해당 world JSON 갱신, `node --experimental-strip-types --test tests/world.test.mjs` 실행.
- 로더·LOD 변경: 중단·변환 보존·거리 전환 검사와 TypeScript·프로덕션 빌드.
- 배포: 검증한 커밋에서 빌드하고 동일 패키지를 저장·게시한 뒤 운영 화면 확인.
- 사진·하드웨어 자료가 없는 항목은 ‘추정’ 또는 ‘미검증’으로 남긴다. 계획 작성과 실제 구현 완료를 구분한다.

## 현재 진행 기록

- 2026-10-01: 운영 v56, 현재 Git 작업 브랜치, 공원 GLB와 Blender 수정본 목록을 확인했다. 사용자 수정본과 이전 계획을 보존했다.
- A: 기존 전망대 항공·현장·목재 산책로 기록을 재검토했다. 2016년/2017년 방문 기록은 오래된 자료이므로 현재 모습의 확정 자료로 취급하지 않는다.
- B: 첫 수관(v57)은 근거리 렌더에서 큰 덩어리와 과한 표면 잡음이 보여 게시하지 않았다. v58에서는 접힌 잎 스프레이와 연결된 가지로 다시 제작했다. 잎 아틀라스는 자체 절차 생성 그림이며 실사 사진이 아니다.
- B: 나무 2,422그루의 원래 바닥 좌표와 수관 범위에서 4종 원형의 가까운/먼 메시를 배치했다. 사용자 원본은 보존하고 `outputs/quality-v58/bitgaram-park-crowns-v58.blend`에 새 수정본을 저장했다. 개별 수종·식재 좌표는 기존 추정 배치이며 현장 실측으로 바뀐 것이 아니다.
- B: 동일 카메라·조명으로 변경 전후 산책로와 조감 렌더를 저장했다. 덩어리 형태가 감소하고 잎 사이 빈 공간과 가지가 보인다. 실제 전체 숲의 수종·계절·밀도 일치는 추가 현장 자료가 필요하다.
- 검증: 보호한 메시 8,370개의 정점·면·변환이 원본 Blender와 일치한다. 가까운/먼 나무 쌍의 변환과 거리 값도 일치한다. 지형·문·벽과 충돌 JSON은 변경하지 않았다. [자산 검증 기록](sources/bitgaram/park-quality-v58-verification.json).
- 용량: GLB 27,833,244→27,702,036바이트, 노드 14,126→13,214, 메시 7,651→6,780. 잎 그림 추가로 **전송 gzip은 4,025,607→4,614,881바이트로 증가**했다. 다운로드 용량 감소 작업이라고 주장하지 않는다. 공유 원형과 거리 전환은 표시 부담을 조절한다.
- D: 불러온 메시의 표시용 병합을 약 6ms 단위로 나눈다. 한 메시 변환·GLTF 해석·큰 병합 자체는 더 오래 걸릴 수 있으므로 전체 로딩이 완전히 비동기라는 뜻은 아니다. 원래 정점·재질·분리 표시 속성을 유지하고 취소 시 임시 형상을 해제한다.
- D: 보행 프레임마다 전체 장면을 순회하던 식생 거리 판정을 준비된 배치 목록으로 변경했다. 공원에서도 고정 변환·필요 시 그림자 갱신을 사용한다. 부분 지도/장소 정보 로딩 실패 시 먼저 읽은 모델도 정리한다.
- D: 현재 브라우저의 최근 120개 가시 산책 프레임 간격·렌더 호출·삼각형 수를 기존 읽기 전용 산책 상태 도구에서 확인할 수 있다. 서버로 전송하거나 저장하지 않는다. 이는 GPU만의 시간이나 실기기 인증이 아니다.
- 검사: 전체 104개 통과, 새 모델 반영 후 보행 73개 재검사 통과, TypeScript와 프로덕션 빌드 성공. 같은 정점·재질 보존, 로딩 도중 타이머 실행, 중단 시 임시 자산 해제, 캐시를 통한 근거리/원거리 전환을 포함한다.
- 웹 확인: 1024×768과 844×390에서 조감·산책·안내창·이동/시선 버튼을 확인했다. 844×390의 120프레임 평균 간격 22.22ms, p95 33.40ms였다. 별도로 기록한 1024×768에서는 평균 26.67ms, p95 83.30ms여서 순간 지연이 남아 있다. [브라우저 관찰](sources/bitgaram/park-browser-quality-check.json)은 한 시점의 데스크톱 브라우저 결과이며 태블릿 성능이나 최악의 장면을 보장하지 않는다. 후속 D/E 단계에서 실제 이동·카메라 회전·기기별 측정을 이어간다.
